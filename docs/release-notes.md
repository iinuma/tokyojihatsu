# リリースノート

Even Hub の審査では `supported_languages` ごとに必要。1〜3 行、コードの変更では
なく利用者にとって何が変わったかを書く。初版はアプリの説明にする。

## 版の記録

Even Hub は Store listing に履歴を持たない。リリースノートも Add build の
瞬間にしか書けず、あとから直せない。**版の履歴を持てるのはここだけ**なので、
アップロードしたかどうかをこの表で管理する。

版は「ビルドの単位」ではなく「**アップロードの単位**」。検証用の `.ehpk` は
`npm run app:pack` で版を上げずに何度でも焼ける。提出すると決めたときにだけ
1 つ上げ、`npm run app:release` を通す。

### ポータルの挙動（実地で確かめたもの）

- **Add build はいつでも通る。** ビルドのアップロード自体は制限されない。
- **Store listing は Submitted 以降は編集できない。** About も説明文も
  スクリーンショットも、審査が終わるまで固まる。
- **新しいビルドを上げても listing のロックは外れない。** 0.4.4 をこの目的で
  上げてみたが効果はなかった。build と listing は別系統で、build を足しても
  listing の状態は動かない。

したがって **listing の内容は、提出する前に正しくなければならない**。
リリースノートと同じで、あとから直せない。`app:release` が提出の前に
ノートとスクリーンショットの両方を確かめるのはこのため。

listing を直せるのは審査が明けてから、次の提出をするまでの間だけ。
**その順番を守る: 審査が明ける → listing を直す → 次のビルドを提出する。**
逆にすると、また 1 審査ぶん待つことになる。

0.3.0〜0.4.2 に穴があるのは、**実機検証のたびに版を上げていた**ため。
検証用ビルドは版を消費しない、という運用にして以降は起きない。

⚠️ **0.3.2 のリリースノートは、ポータルにしか残っていない。** 提出時に
直接入力したため、ここに控えが無い。ポータルから読み出せたら下に追記する。
これが「記す場所がほとんど無い」ことの実害そのもので、以降は
`app:release` が文面の用意を強制する。

## tagline（ポータルのプロジェクト設定・50 文字以内）

```
首都圏の駅で、見上げれば次の電車まであと何分か
```

23 文字。体験（見上げる）と対応範囲（首都圏）の両方を入れている。
見上げ表示が既定なので、実際の振る舞いとも一致する。

駅数や事業者名は書かない。チャレンジ限定ライセンスのデータが 2027-03-12 で
切れると 1844 駅 → 440 駅に戻るうえ、Submitted 以降はメタデータを編集
できないため、数字を書くと実態とずれたまま直せなくなる。「首都圏」なら
期限の前後どちらでも成り立つ。

## 0.5.0

**山手線の全 30 駅で、内回りと外回りが同じ「大崎方面」になっていた。** 方面ラベルを
平日時刻表の最頻行先から作っているため、**環状線では両方向とも同じ駅が最頻になる**。
山手線はほぼ全列車が大崎を通る。都営大江戸線の都庁前も同じ状態だった。

衝突したときだけ、その方向の**隣の駅**をラベルにするようにした。隣の駅は必ず
方向ごとに違うので確実に区別がつく。品川なら「高輪ゲートウェイ方面（内回り）」と
「大崎方面（外回り）」になる。**全 1844 駅で重複がゼロ**になったことを確認済み。

⚠️ 内回り / 外回りの向きは推測せず、列車時刻表（`odpt:TrainTimetable`）で
実際の走行順を確かめた。外回りは「高輪ゲートウェイ → 品川 → 大崎」、内回りは
「大崎 → 品川 → 高輪ゲートウェイ → 田町」。**品川で東京方面は内回り。**

あわせて時刻表データを再取得した（取得日時 2026-07-17 → 2026-09-24）。
ODPT ガイドライン 2.2.2 の「更新通知から 1 週間以内」にも効く。

「データについて」画面も詰めた。0.4.x で文面が 12 行まで伸び、**ガイドライン
2.2.1 が求める取得日時が画面外へ押し出されていた**。スクロールすれば読めるが、
「容易にアクセスできる画面上」とは言いにくい。9 行に収め、必須の 4 点が
スクロールなしで読めるようにした。取得日時は秒とタイムゾーンを落として短く出す。

## 0.4.4

掲載中のスクリーンショット（05-about.png）に、0.4.3 で直したはずの
「遅延は反映されません」が映ったままだった。**ストアの画像がアプリの実装と
矛盾している**状態だったので差し替える。03 / 04 も 0.4 で足した
「○時点 遅れなし」の行が写っていなかったので撮り直した。

⚠️ **アプリのビルドは 0.4.3 と 1 バイトも変わっていない**（同一ハッシュを確認済み）。
0.4.3 以降に足した bitmap.ts / mercator.ts / stationmap.ts / tileink.ts は
どれも probe 専用で、app/src から参照していないため。

Store listing の画像は build とは別枠なので、本来この差し替えに新しいビルドは
要らない。審査中で listing を編集できず、再提出が必要な場合にだけこの版を使う。
