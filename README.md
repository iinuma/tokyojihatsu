# 東京次発

Even Realities G2 向けの駅時刻表カウントダウン。近くの駅と方面を選ぶと、次の電車の
発車予定時刻までの残り時間を G2 上に表示する。

企画・要件は Notion の
[東京次発 — Even G2 時刻表カウントダウン アプリ概要・要件](https://app.notion.com/p/3e21b0c05d9b81caacbff622883e3349)
にある。このリポジトリはその実装。

## 対応範囲

ODPT で駅時刻表が取得できる **7 事業者 440 駅**。都道府県では絞らない。

東京メトロ / 都営（都電荒川線・日暮里舎人ライナーを含む） / 横浜市営 / つくばエクスプレス /
多摩都市モノレール / ゆりかもめ / りんかい線

JR東日本・京急・東急・京王・小田急・西武・東武・相鉄は ODPT に駅時刻表がないため対応できない。
近傍駅の候補は「時刻表が実在する駅」だけに限っている。

## 使い方

```bash
npm install
cp .env.example .env   # ODPT_TOKEN を書く
npm run build:master   # 駅マスタを生成（ODPT から約 80MB 取得する。数分かかる）
```

検証用 CLI:

```bash
# 現在地の近くの駅
npm run next -- --lat 35.6637 --lng 139.7839

# 駅名から次発を出す（方面の指定は省略可）
npm run next -- --station 月島
npm run next -- --station 月島 --direction 光が丘

# 時刻を指定して境界条件を確かめる
npm run next -- --station 月島 --direction 光が丘 --at 2026-09-25T00:15
```

```bash
npm test        # ネットワーク不要
npm run typecheck
```

## 構成

```

├─ odpt/          ODPT v4 API の型とクライアント
│  ├─ types.ts
│  └─ client.ts   baseUrl を差し替えればプロキシ経由にできる
├─ core/          描画に依存しないロジック。G2 層も CLI もここを呼ぶ
│  ├─ geo.ts        距離計算・近傍検索
│  ├─ calendar.ts   祝日と ODPT カレンダー種別の判定
│  ├─ departures.ts 次発・次々発の算出
│  ├─ master.ts     駅マスタの型・駅グループ化
│  └─ service.ts    駅選択から次発取得までの実行時ロジック
└─ cli/next.ts    検証用 CLI
app/             カウントダウン本体（G2 プラグイン）
├─ app.json      マニフェスト（権限・ホワイトリスト）
└─ src/
   ├─ layout.ts    576x288 の座標と文字幅の扱い
   ├─ screens.ts   各画面の組み立て
   ├─ selection.ts 選んだ駅・方面の記憶
   └─ main.ts      画面遷移とブリッジ配線
probe/           実機検証プラグイン（本体とは別アプリ）→ probe/README.md
scripts/build-master.ts  駅マスタ生成
data/stations.json       生成物（約 500KB）
```

駅マスタには時刻表の本体を入れず、`駅 × 方面 → 時刻表 ID` だけを持つ。発車時刻は実行時に
ID 指定で 1 レコードずつ引く。データ更新のたびにアプリをリリースし直さずに済ませるため。

## 実装上の要点（実測で分かったこと）

- **終電は 0 時台で表記される。** `25:00` ではなく `00:07` `00:21`。時刻表の配列は運行順なので、
  前の要素より小さくなったところが日跨ぎ。時刻の文字列だけでソートすると終電が始発の前に来る。
- **都電荒川線だけカレンダー種別が違う。** 他の 6 事業者は `Weekday` / `SaturdayHoliday` の
  2 種だが、都電荒川線は `SaturdayHoliday` を持たず `Saturday` と `Holiday` に分かれている。
  そのため `calendarFor()` は単一の値ではなく優先順の候補リストを返す。
- **祝日判定は ODPT から取れない。** カレンダー種別は時刻表側にあるが「今日がどちらか」の
  紐付けがない。内閣府告示の規則をそのまま実装しているのでテーブルの更新は要らない
  （春分・秋分の近似式は 1980–2099 で有効）。
- **方面名は ODPT のままだと分かりにくい。** `odpt:RailDirection` は「外回り」「北行」のような
  抽象的な名前が多い。マスタ生成時に平日時刻表の最頻行先を集計し「光が丘方面」に変換している。
- **行先には直通先の他社線の駅が出る。** 7 事業者の駅名辞書だけでは足りないので、
  マスタ生成時に直通先事業者の駅名と列車種別も取り込んでいる。
- 年末年始（12/29–1/3）に土休日ダイヤを走らせる事業者があるが、扱いは事業者ごとに異なり
  ODPT からは判別できない。現在は平日として扱っている。

## ODPT ライセンス上の義務

[開発者ガイドライン](https://developer.odpt.org/terms/data_basic_use_guideline.html)より。
公開時に必要なもの。**まだ実装していない。**

- **アプリ内に 3 点を表示する**（3.1）… 公共交通オープンデータセンター提供であること /
  正確性・完全性が保証されないこと / 開発者の問い合わせ先
- **データの取得日時を表示する**（2.2.1）… 常時表示の義務はない。Contextual Menu から
  開ける情報画面に上記とまとめて置けばよい。取得日時はマスタの `sourceDate` にある
- **更新通知から 1 週間以内にデータを更新する**（2.2.2）… 公開後ずっと続く運用義務。
  時刻表を `.ehpk` に同梱せずプロキシ側で定期取得する設計にして、アプリのリリースなしで
  更新できるようにする
- ロゴ画像と路線ラインカラーは加工禁止。G2 は 4bit モノクロなので再現できない → 使わない

API キーは `.ehpk` に入れてはいけない（「anyone with the released .ehpk can extract bundled
contents」）。個人利用なら ODPT を直接叩けるが、Even Hub 公開時はプロキシが必須。

## カウントダウン本体

```bash
npm run app:dev     # dev サーバー（:5175）
npm run app:qr      # 実機に読ませる QR
npm run app:pack    # 検証用。版を上げずに何度でも焼ける
npm run app:release # 提出用。ノートが揃っていなければ止まる
```

**版はビルドの単位ではなく、アップロードの単位**。実機検証のために
`app.json` の `version` を上げる必要はない。上げるのは提出すると決めたときだけで、
`app:release` がその前に次を確かめる。

- `docs/release-notes.md` に、その版の節が `supported_languages` 全部ぶんあるか
- `v<version>` のタグがまだ無いか（あれば上げ済み）
- 作業ツリーがクリーンか

通れば `.ehpk` を作り、**Add build に貼り付ける文面をそのまま出力する**。
Even Hub はアップロードの瞬間にしかノートを書けず、あとから直せないので、
あの画面で文章を考えないための仕掛け。

画面は 3 つ。近くの駅を選び、方面を選ぶとカウントダウンに入る。前回の選択を覚えていて、
同じ駅の 500m 以内にいれば起動してすぐカウントダウンになる。

```
                        次発 20:23
        あと 4:05        次々発 20:30


月島　大江戸線・光が丘方面
時刻表ベース
```

コンテキストメニューに「駅を選び直す」「常時表示／見上げ表示の切替」「データについて」
「終了」を置いた。「データについて」は ODPT ガイドライン 3.1 の必須表示 3 点と取得日時を
まとめた画面で、常時表示の義務がないぶんここに逃がしている。

**見上げ表示が既定。** 下を向いている間はカウントダウンを空にする。IMU の実測から
`pitch = asin(x)` で頭の上下角が出せると分かったので（下記）、HeadUp Display が使えなくても
同じ体験を自前で作れる。ヒステリシス（入り 20°／抜け 12°）を入れてあるのは、閾値ちょうどで
頭が揺れると表示がばたつくため。

**ODPT のキーはプロキシ側が持つ**ので、アプリのバンドルには入らない（`VITE_ODPT_PROXY`）。
プロキシを使わずキーを直接埋める経路（`VITE_ODPT_TOKEN`）も残してあるが、
`.ehpk` は展開できるので公開ビルドでは使わない。

## プロキシ

`proxy/` に ODPT への中継がある。Lambda Function URL 1 本だけの構成で、
時刻表そのものは持たず都度 ODPT を引く。

```bash
npx cdk deploy      # 更新（AWS アカウントは作業ディレクトリで決まる）
npx cdk diff        # 差分だけ見る
```

役目は 2 つあり、どちらも ODPT のライセンス由来。

1. **API キーの秘匿。** `.ehpk` は誰でも展開できるのでキーを同梱できない。
   キーは SSM の SecureString にだけ置き、Lambda が実行時に読む。
2. **データ更新義務。** 開発者ガイドライン 2.2.2 の「更新通知から 1 週間以内」は、
   ロールバック不可・全リリース審査経由の Even Hub ではアプリ更新で満たせない。
   中継が都度 ODPT を引けば構成上自動で満たされる。

さらに、**基本ライセンス・限定ライセンスとも第 8 条 4(1) が
「第三者が再利用可能な状態での公開・再配布・公衆送信」を禁じている**ため、
URL を知るだけで JSON が取れる状態にはしない。アプリは共有鍵
（`X-Tokyojihatsu-Key`）を送り、一致しないリクエストは 403 で返す。
IP ごとに毎分 60 リクエストの上限も設けてある。

`.ehpk` から鍵は取り出せるので完全な防御にはならない。ここで目指すのは
「誰でも叩ける API として公開しない」ことであって、それ以上ではない。

## 実機検証（probe）

実機でしか決まらないことを測るための最小プラグインが [probe/](probe/) にある。
手順と読み方は [probe/README.md](probe/README.md)。

```bash
npm run probe:dev      # ブラウザ / QR サイドロード用の dev サーバー
npm run probe:qr       # 実機に読ませる QR（LAN IP 自動）
npm run probe:pack     # dist/tokyojihatsu-probe.ehpk を作る
```

**ロック 5 分の検証は Beta build でしかできない。** シミュレータと QR サイドロードは
ロックした瞬間に WebView が止まり、Private build も「survive briefly but don't pass the
5-minute lock test」と明記されている。この 1 点で設計（案1「出しっぱなし」か
案2「IMU で自前の見上げ検出」か）が決まるので、先に潰す。

### 実機で確定したこと（2026-09-21）

- **日本語は表示できる。** 「月島 大江戸線 光が丘方面」が漢字を含めて完全に読めた。
- **IMU の単位は G（重力加速度）。** 静止時 `|v| = 0.97`。FAQ の「A units table is still TBD」に
  対する実測の答え。頭を振ったときの振れ幅は x=1.6 / y=0.5 / z=0.7 で、単一軸が重力だけで
  動ける最大が 2.0 なので **x 軸が頭の前後傾き**。よって `pitch = asin(x)`、**見上げると +**。
- **見上げ表示の体験が成立した。** 下を向いている間だけ本文を空にするデモを実機で試して、
  ちらつきも遅延もないことを確認。
- SDK が `setInterval` を差し替えていることを実機で確認（`patched:y`）。タイマー精度は正常
  （`up 1m31s` に対し `tick 93`）。

まだ測れていないのは **ロック 5 分 → 復帰**（Beta build が必要）と、
**G2 メニューからの起動操作数**、地下・駅の密集地での位置精度。

調査中に分かった、要件に書かれていなかったこと:

- **SDK は `setInterval` を差し替える**（`[ShadowTimers] ... queued`）。公式ドキュメントに
  記載がない。「タイマーが飛んだ」だけでは WebView が止まったのか SDK が溜めていたのか
  区別できないので、probe は SDK 読み込み前の素のタイマーも保持して両方を測る。
- **`FOREGROUND_ENTER_EVENT` / `FOREGROUND_EXIT_EVENT` が SDK の enum にある。**
  ドキュメントのイベント表には載っていない。前面・背面の遷移を取れる可能性がある。
- **ホスト側の保存領域が使える**（`bridge.setLocalStorage` / `getLocalStorage`）。
  WebView の localStorage とは別なので、probe は両方に書いてどちらが生き残るかも見る。
- **実機のコンソールはスマホアプリの開発者モード画面から読める。**
